CLI that writes structured Markdown notes into an [Obsidian](https://obsidian.md) vault — built so Claude Code (or any script) can persist documentation/decisions as notes you can browse and search natively in Obsidian.

Part of a 3-repo integration:

- **`obsidian-notes-cli`** (this repo) — writes the notes.
- [`obsidian-claude-notes`](https://github.com/jeffersongoncalves/obsidian-claude-notes) — Obsidian plugin: sidebar of Claude Code notes, command to trigger the CLI from inside Obsidian, live refresh.
- [`claude-code-obsidian-notes`](https://github.com/jeffersongoncalves/claude-code-obsidian-notes) — Claude Code plugin (skill + `/obsidian-note` command) that shells out to this CLI.

## Install

```bash
composer global require jeffersongoncalves/obsidian-notes-cli
```

Or download the `obsidian-notes.phar` from the [latest release](https://github.com/jeffersongoncalves/obsidian-notes-cli/releases).

## Usage

```bash
# One-time: scaffold .claude-notes.json + base folder in a vault
obsidian-notes vault:init /path/to/vault

# Write a note (body piped via stdin)
echo "We chose SQLite over Postgres for the CLI cache." \
  | obsidian-notes note:create --project=my-app --title="Decision: SQLite" --tags=architecture --vault=/path/to/vault

# List notes generated by Claude Code
obsidian-notes note:list --vault=/path/to/vault

# Update the CLI itself
obsidian-notes self-update
```

Set `OBSIDIAN_VAULT` to skip passing `--vault` every time.

## The `.claude-notes.json` contract

A vault's `.claude-notes.json` (created by `vault:init`, or hand-written) is the single source of truth shared with the [Obsidian plugin](https://github.com/jeffersongoncalves/obsidian-claude-notes) — both read the same file, nothing is duplicated:

```json
{
  "folderPattern": "Claude Notes/{project}/{date}-{slug}.md",
  "frontmatterDefaults": { "source": "claude-code", "tags": [] },
  "bridgePort": 27124
}
```

Every note gets this frontmatter: `source`, `project`, `title`, `tags`, `created`, `updated`. The Obsidian plugin's sidebar filters on `source: claude-code`.

### The bridge

After writing a file, the CLI makes a best-effort `POST http://127.0.0.1:<bridgePort>/notes` to the Obsidian plugin, so its sidebar refreshes instantly. If the bridge is off or Obsidian isn't running, the call is silently ignored — the file is already on disk, and Obsidian picks up external changes natively the next time it gains focus.
